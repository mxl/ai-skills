# 03: Импорт выбранных встреч через meeting-transcript

Status: resolved
Blocked by: 02

## What to build

Пользователь выбирает встречи из объединённого предпросмотра и импортирует готовые транскрипты существующим механизмом meeting-transcript. Одна встреча получает один канонический транскрипт независимо от количества источников; повторный импорт не создаёт дубликат.

## Acceptance criteria

- [x] Готовый транскрипт Amanu является основным кандидатом; несколько разных готовых транскриптов требуют выбора пользователя, а не автоматического объединения.
- [x] Документированный адаптер формирует канонический вход, сохраняя текст, метки говорящих, порядок и поддерживаемые метаданные. Исходный транскрипт не переписывается.
- [x] Используется существующая валидация и атомарная запись канонического импорта; байтово идентичный результат остаётся без изменений.
- [x] В отдельном машинно читаемом Markdown-состоянии проекта сохраняются идентичность события, связи всех обнаруженных исходников и место импортированного транскрипта. Постоянные служебные JSON не создаются.
- [x] Имена исходников не являются единственным ключом встречи. Повторный запуск распознаёт ранее импортированное событие и не создаёт вторую папку встречи.
- [x] При отсутствии готового транскрипта встреча отмечается как незакрытая; распознавание предлагается отдельно и автоматически не запускается. Другие согласованные готовые встречи продолжают импортироваться.
- [x] Неоднозначный проектный адресат импорта требует уточнения; проектная настройка назначения применяется в однозначном случае.
- [x] Импорт не запускает резюмирование, распознавание, создание задач или переименование оригиналов. Существующие разрешения и ограничения meeting-transcript сохранены.
- [x] Публичные проверки покрывают точное сохранение содержания, выбор конкурирующих транскриптов, оба источника одной встречи, повторный импорт, невалидный вход без записи и продолжение при одном отсутствующем транскрипте.
- [x] Состояние сохраняется атомарно. Продвижение границы периода и полная проверка восстановления после сбоя остаются отдельными задачами.

## Comments

### Implementation qualification

Нативный адаптер Amanu реализован после проверки скачанного корпуса. Структурированный JSON преобразуется в памяти, без дополнительных файлов в источнике; сохраняются точный текст, метки, порядок, UTC-время записи и каноническое объединение соседних реплик с полностью одинаковой меткой через перевод строки. Непредставимое содержимое остаётся pending вместо исправления. Исходные миллисекундные границы сегментов остаются в неизменённом и хешированном JSON; фиксированный канонический шаблон содержит время записи целиком. План привязывает сырьевые сигнатуры и фактический event-title-specific хеш результата; apply и публикация проверяют их повторно. Проверено 66 тестами и read-only конвертацией 32/32 реальных пакетов. Review замечаний P1/P2 не оставил. Реальных импортов не выполняли.
