# 04: Подтверждаемое переименование исходников

Status: resolved
Blocked by: 03

## What to build

Пользователь проверяет план новых имён и явно разрешает переименование оригинальных OBS-файлов и верхнеуровневых пакетов Amanu. Переименование сохраняет связь с уже импортированной встречей и не меняет внутреннее устройство пакетов.

## Acceptance criteria

- [x] План содержит исходный путь, выбранное событие, основание сопоставления и новое имя. До подтверждения нет переименований; отклонённые или неоднозначные строки не выполняются.
- [x] Имя формируется из плановых даты и времени начала события в проектном часовом поясе и названия: YYYY-MM-DD HH-mm Название встречи.
- [x] Расширение OBS сохраняется. У Amanu меняется только верхнеуровневое имя папки, без изменения внутренних имён и содержимого.
- [x] Недопустимые символы обрабатываются предсказуемо. Коллизии не перезаписывают существующие артефакты; выбранное безопасное поведение показано пользователю в плане.
- [x] Непосредственно перед изменением проверяются актуальность исходника, назначения, подтверждённого сопоставления и безопасность операции. Изменившийся план не исполняется как ранее одобренный.
- [x] Активные либо непроверяемые записи и пакеты остаются без переименования с объяснением причины. Один маркер обработки не считается достаточным доказательством активности или безопасности.
- [x] Исходные и текущие пути фиксируются в проектном состоянии; импортированная встреча остаётся связана с обоими источниками после переименования и повторного обнаружения.
- [x] Обновление имени из-за последующего изменения события пока не выполняется автоматически и обрабатывается отдельной задачей.
- [x] Публичные проверки покрывают отсутствие согласия, частично одобренный план, часовые пояса, коллизии, изменение исходника после предпросмотра, безопасность пакетов и сохранение связей.
- [x] Исполняемые тесты используют временные артефакты; разрешение на разработку не считается подтверждением переименования реальных записей.

## Native release follow-up acceptance

- [x] Нативные OBS и Amanu могут успешно переименовываться после явного attestation, проверенного завершённого артефакта, двух стабильных наблюдений и калиброванной проверки открытых дескрипторов; safety больше не всегда false.
- [x] Положительный контроль PID/FD/device/inode виден в той же области lsof; исключается только собственный контрольный дескриптор. Другие открытые файлы, предупреждения, отсутствие контроля, неполная область или ошибка дают busy/unknown и отказ.
- [x] Проверка повторяется непосредственно перед переименованием; замена источника/родителя, поздний writer, изменение inventory и коллизии не приводят к переименованию чужого артефакта или продвижению штампа после ошибки.
- [x] Публичные тесты с реальным lsof показывают успешные переименования обоих нативных форматов и отказ активным/неопределённым источникам. Оригиналы пользователя не меняются при разработке.

## Comments

### Verification and qualification

Нативный success-path завершён: подтверждённые источники OBS/Amanu могут переименовываться после наблюдения завершённости, стабильности и освобождения, а не остаются всегда unsafe. Финальная серия: 81 тест OK, без пропусков. Успешные нативные тесты используют реальный системный lsof и настоящий сгенерированный MP4, проверяют календарные имена и неизменность содержимого Amanu. Отказы покрывают открытые дескрипторы, поздних writers, неизвестную/неполную инспекцию, маркеры/перезапуск обработки, изменение inventory и замены источника/родителя. Проверены поздняя коллизия и rollback без перезаписи чужого оригинального имени. Оба независимых review после исправлений не оставили P1/P2. Это наблюдаемое освобождение плюс scoped attestation, не абсолютная блокировка производителя. Реальные записи пользователя не переименовывались.
