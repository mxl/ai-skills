# 05: Инкрементальный импорт и незакрытые встречи

Status: resolved
Blocked by: 03

## What to build

Успешный импорт сохраняет проектную границу проверенного периода. Следующий запрос автоматически обрабатывает новый период и незакрытые старые встречи, поэтому поздние записи и транскрипты не теряются, а явно отклонённые встречи не предлагаются повторно.

## Acceptance criteria

- [x] Проектное Markdown-состояние хранит начальную дату и конец успешно обработанного периода с часовым поясом отдельно от настроек.
- [x] При первом запуске начальная дата запрашивается. Конец периода фиксируется на старте; следующие запуски начинают с сохранённой границы.
- [x] Ещё не завершившиеся события не теряются при продвижении границы: они подлежат повторной проверке после завершения.
- [x] Отсутствующая запись, неготовый транскрипт и неоднозначное соответствие сохраняются как незакрытые встречи с причиной и устойчивой идентичностью.
- [x] Незакрытые встречи проверяются при следующих запусках независимо от их возраста относительно границы. Готовые встречи продолжают обрабатываться.
- [x] Явно отклонённые встречи запоминаются и автоматически не предлагаются снова.
- [x] Граница продвигается только после успешного завершения согласованного пакета; учтённые незакрытые встречи сами по себе не являются ошибкой всего запуска.
- [x] Ошибка или прерывание сохраняет прежнюю границу. Перекрытие на границе безопасно благодаря дедупликации по идентичности события.
- [x] Успешные результаты отдельных встреч сохраняются для безопасного повтора; состояние не заменяется частично записанным документом.
- [x] Публичные проверки охватывают несколько последовательных запусков, поздние записи и транскрипты, границу периода, ещё идущие события, отказы, неоднозначности и ошибку без продвижения штампа.
- [x] Сценарий работает без обязательного переименования исходников; зависимость от задачи переименования не вводится.
