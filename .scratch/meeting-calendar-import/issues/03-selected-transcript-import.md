# 03: Импорт выбранных встреч через meeting-transcript

Status: ready-for-agent
Blocked by: 02

## What to build

Пользователь выбирает встречи из объединённого предпросмотра и импортирует готовые транскрипты существующим механизмом meeting-transcript. Одна встреча получает один канонический транскрипт независимо от количества источников; повторный импорт не создаёт дубликат.

## Acceptance criteria

- [ ] Готовый транскрипт Amanu является основным кандидатом; несколько разных готовых транскриптов требуют выбора пользователя, а не автоматического объединения.
- [ ] Документированный адаптер формирует канонический вход, сохраняя текст, метки говорящих, порядок и поддерживаемые метаданные. Исходный транскрипт не переписывается.
- [ ] Используется существующая валидация и атомарная запись канонического импорта; байтово идентичный результат остаётся без изменений.
- [ ] В отдельном машинно читаемом Markdown-состоянии проекта сохраняются идентичность события, связи всех обнаруженных исходников и место импортированного транскрипта. Постоянные служебные JSON не создаются.
- [ ] Имена исходников не являются единственным ключом встречи. Повторный запуск распознаёт ранее импортированное событие и не создаёт вторую папку встречи.
- [ ] При отсутствии готового транскрипта встреча отмечается как незакрытая; распознавание предлагается отдельно и автоматически не запускается. Другие согласованные готовые встречи продолжают импортироваться.
- [ ] Неоднозначный проектный адресат импорта требует уточнения; проектная настройка назначения применяется в однозначном случае.
- [ ] Импорт не запускает резюмирование, распознавание, создание задач или переименование оригиналов. Существующие разрешения и ограничения meeting-transcript сохранены.
- [ ] Публичные проверки покрывают точное сохранение содержания, выбор конкурирующих транскриптов, оба источника одной встречи, повторный импорт, невалидный вход без записи и продолжение при одном отсутствующем транскрипте.
- [ ] Состояние сохраняется атомарно. Продвижение границы периода и полная проверка восстановления после сбоя остаются отдельными задачами.

## Comments

### Implementation qualification

Публичный поток выбора и канонического импорта реализован для нормализованного адаптерного входа с готовым каноническим Markdown. Преобразование НАТИВНОГО Amanu JSON/Markdown не реализовано без проверенного образца. Оставшаяся часть зависит от снятия блокировки задачи 02. Поддержка синтетического контракта и прямого канонического импорта не означает завершения нативного адаптера.
