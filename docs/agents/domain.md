# Domain Docs

## Layout

This repository uses a single-context layout: `GLOSSARY.md` at the repository root and architectural decision records in `docs/adr/`.

## Before exploration and design

Read the root `GLOSSARY.md`, if present, and ADRs relevant to the area being explored or changed. If either is absent, proceed without creating placeholder documents. Create domain documentation when terminology or architectural decisions are actually resolved.

## Vocabulary

Use glossary terms consistently in specifications, issue titles, designs, and tests. When a needed concept is missing, identify the terminology gap for domain modeling rather than silently assigning a competing meaning.

## Architectural decisions

If a proposal conflicts with an existing ADR, cite that ADR and explain the conflict explicitly before proposing to reopen the decision.
